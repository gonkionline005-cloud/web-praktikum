# Личная библиотека

Учебный проект по курсу «Практический курс веб разработки» (React + TypeScript + Node + Supabase), ПГУ им. Т.Г. Шевченко, физико-технический институт.

Приложение для учёта книг: что читаю сейчас, что хочу прочитать, что уже прочитано, плюс заметки по книгам. Каждый пользователь видит и изменяет только свои книги.

**Автор:** Пержан Татьяна, группа ФТ24ДР62ПИ1

## Сценарий

Пользователь регистрируется или входит в аккаунт, просматривает свой список книг, фильтрует его по статусу, открывает карточку книги, добавляет, редактирует и удаляет книги. Жанр выбирается из справочника, который загружается из Supabase. Книги хранятся в базе данных и остаются после обновления страницы и повторного входа.

## Стек

React, TypeScript, Vite, React Router, Supabase (PostgreSQL, Auth), `@supabase/supabase-js`.

## Версия Node

24.21.0 (см. файл `.node-version`)

## Как запустить

Из корня проекта:

```bash
cd frontend
npm ci
```

Создайте файл `frontend/.env.local` по образцу `frontend/.env.example` и подставьте URL и publishable key своего учебного проекта Supabase. Затем:

```bash
npm run dev
```

Приложение откроется на http://localhost:5173. После изменения `.env.local` dev-сервер нужно перезапустить.

## Страницы приложения

- `/` — перенаправляет на список книг
- `/auth` — вход и регистрация
- `/books` — список книг текущего пользователя с фильтром по статусу (нужен вход)
- `/books/new` — добавление книги (нужен вход)
- `/books/:id` — карточка книги, удаление с подтверждением (нужен вход)
- `/books/:id/edit` — редактирование книги (нужен вход)
- любой другой адрес — страница «не найдено»

Гость при открытии личной страницы перенаправляется на `/auth`. Это удобство интерфейса, а не защита данных: реальную защиту обеспечивают права и RLS в базе.

## Возможности

- Просмотр списка и карточки книги

## Схема данных

| Таблица | Назначение | Ключи и связи | Доступ |
|---|---|---|---|
| `genres` | справочник жанров | PK `id` (text), уникальное `name` | публичная: только чтение для `anon` и `authenticated` |
| `books` | личные записи пользователя | PK `id` (uuid); `owner_id` → `auth.users(id)`; `genre_id` → `genres(id)` | личная: только `authenticated`, только свои строки |

Ограничения `books`: название 3–100 символов, автор не пустой, статус `want` / `reading` / `done`, оценка `NULL` или от 1 до 5. В интерфейсе «оценка не задана» хранится как `0`, в базе как `NULL`; преобразование выполняет `frontend/src/services/books.ts`.

## Модель доступа

- **genres** — читать могут все, включая гостей. Изменять справочник из браузера нельзя.
- **books** — читать, добавлять, изменять и удалять может только вошедший пользователь и только свои записи.

Доступ ограничен правами PostgreSQL (`GRANT`) и политиками Row Level Security. У `anon` прав на `books` нет. У `authenticated` есть `SELECT`, `INSERT`, `UPDATE`, `DELETE`, а четыре отдельные политики сравнивают `owner_id` с `auth.uid()`: `USING` ограничивает существующие строки, `WITH CHECK` не даёт вставить или передать запись другому владельцу. Столбец `owner_id` заполняется самой базой (`default auth.uid()`), клиент его не передаёт.

## SQL

- схема, права и RLS (ЛР 5): `supabase/migrations/202610250001_initial_schema.sql`;
- политики владельца для `books` (ЛР 6): `supabase/migrations/202610260001_books_owner_policies.sql`;
- справочные данные: `supabase/seed.sql`.

Порядок применения в SQL Editor: 1) первая миграция, 2) `seed.sql`, 3) вторая миграция. Seed можно повторять: он обновляет строки по `id`.

## Настройка Supabase Auth

- Authentication → Providers → Email: вход по email и паролю включён. Подтверждение email: **<включено / выключено — впиши фактическое состояние>**.
- Authentication → URL Configuration: Site URL `http://localhost:5173`, в Redirect URLs добавлен `http://localhost:5173`. При другом порте укажите свой.

## Переменные окружения

Значения в репозиторий не попадают. Названия переменных:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Образец: `frontend/.env.example` (в нём только заглушки). Во frontend допустим только publishable key. Secret key, `service_role` и пароль базы во frontend и в Git не хранятся.

## Структура frontend

- `src/lib/supabase.ts` — единый клиент Supabase;
- `src/hooks/useAuth.ts` — состояние сессии (`checking` / `guest` / `authenticated`);
- `src/hooks/useGenres.ts` и `src/services/genres.ts` — загрузка справочника;
- `src/services/books.ts` — запросы к таблице `books` и преобразование полей;
- `src/components/RequireAuth.tsx` — маршрут только для вошедших;
- `src/components/BooksGate.tsx` — состояния загрузки и ошибки списка;
- `src/pages/AuthPage.tsx` — вход и регистрация.
