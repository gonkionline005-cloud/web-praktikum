# Личная библиотека

Учебный проект по курсу «Практический курс веб разработки» (React + TypeScript + Node + Supabase), ПГУ им. Т.Г. Шевченко, физико-технический институт.

Приложение для учёта книг: что читаю сейчас, что хочу прочитать, что уже прочитано, плюс заметки по книгам.

**Автор:** Пержан Татьяна, группа ФТ24ДР62ПИ1

## Сценарий

Пользователь просматривает список книг, фильтрует его по статусу, открывает карточку книги, добавляет, редактирует и удаляет книги. При добавлении и редактировании жанр выбирается из справочника, который загружается из базы данных Supabase.

## Стек

React, TypeScript, Vite, React Router, Supabase (PostgreSQL), `@supabase/supabase-js`.

## Версия Node

24.21.0 (см. файл `.node-version`)

## Как запустить

Из корня проекта:

```bash
cd frontend
npm ci
```

Создайте файл `frontend/.env.local` по образцу `frontend/.env.example` и подставьте URL и publishable key своего учебного проекта Supabase. Затем:

```bash
npm run dev
```

Приложение откроется на http://localhost:5173. После изменения `.env.local` dev-сервер нужно перезапустить.

## Проверка сборки

Остановите dev через Ctrl+C, затем в `frontend`:

```bash
npm run build
npm run preview
```

## Страницы приложения

- `/` — перенаправляет на список книг
- `/books` — список книг с фильтром по статусу
- `/books/new` — добавление книги
- `/books/:id` — карточка книги (редактирование, удаление с подтверждением)
- `/books/:id/edit` — редактирование книги
- любой другой адрес — страница «не найдено»

## Возможности

- Просмотр списка и карточки книги
- Добавление, редактирование и удаление книги одной формой с проверкой ввода

## Справочник жанров в Supabase (ЛР 5)

Справочник жанров хранится в таблице `public.genres` в Supabase и читается формой через `@supabase/supabase-js`:

- клиент: `frontend/src/lib/supabase.ts`;
- запрос и проверка ответа: `frontend/src/services/genres.ts`;
- состояния загрузки: `frontend/src/hooks/useGenres.ts`.

В книге хранится `id` жанра (например `novel`), а пользователю показывается `name` («Роман»). Файл `public/demo/genres.json` из ЛР 4 больше не используется.

### Схема данных

| Таблица | Назначение | Ключи и связи | Доступ |
|---|---|---|---|
| `genres` | справочник жанров | PK `id` (text), уникальное `name` | публичная: SELECT для `anon` и `authenticated`, изменять нельзя |
| `books` | личные записи пользователя | PK `id` (uuid); `owner_id` → `auth.users(id)`; `genre_id` → `genres(id)` | личная: RLS включён, прав и политик для клиентских ролей нет до ЛР 6 |

Ограничения `books`: название 3–100 символов, автор не пустой, статус `want` / `reading` / `done`, оценка `NULL` или от 1 до 5.

### SQL

- схема, права и RLS: `supabase/migrations/202610250001_initial_schema.sql`;
- справочные данные: `supabase/seed.sql`.

Порядок применения: в SQL Editor сначала выполнить миграцию, затем seed. Seed можно повторять: он обновляет строки по `id`.

### Переменные окружения

Значения в репозиторий не попадают. Названия переменных:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Образец: `frontend/.env.example`. Во frontend допустим только publishable key. Secret key, `service_role` и пароль базы во frontend и в Git не хранятся.

## Текущие ограничения

Основные записи (книги) хранятся только в памяти приложения (состояние `App`). После обновления страницы возвращаются демонстрационные книги из `frontend/src/data/books.ts`. Постоянным в ЛР 5 стал только справочник жанров. Личная таблица `books` закрыта от браузера до ЛР 6 (Supabase Auth).

## Использование ИИ

Использовала ИИ (Claude) в процессе работы над лабораторными:

- ЛР 1–2: как связаны `index.html`, `main.tsx` и `App.tsx`; ошибка «detected dubious ownership» при работе с флешкой; связка BrowserRouter / Routes / Route / Outlet и передача props;
- ЛР 3–4: разбор состояния в `App`, формы с черновиком, фильтра, загрузки справочника через `fetch`, `useEffect` и `AbortController`;
- ЛР 5: объяснение SQL-схемы, GRANT и RLS, настройки Supabase и подключения клиента.

Весь код проверяла сама: запускала `npm run dev`, смотрела результат в браузере и в Network, проверяла ошибки, пустой справочник и запрет клиентской записи, пересобирала после изменений. Пароль базы и ключи ИИ не передавались.
